V5 (1.x) features compared with V6 (2.x)

This report lists what the V5 SDK on origin/main (last release v1.0.7) gave users, and what the V6 SDK on feat/v6-sdk keeps, changes, or drops. It was written on 2026-10-16 from git show origin/main:<path> and the feat/v6-sdk working tree. The migration guide already records some of these gaps for users.

Status values:

  • Kept: V6 has the same capability, maybe under a new name.
  • Partial: V6 has part of it, or needs a workaround.
  • Missing: V6 has nothing for it.

Current request routing

V6 and V5 calls use separate transport paths. The V5 path supports the query and batch endpoints that have no V6 equivalent.

Open the interactive V5/V6 routing explorer to select a transport path and inspect its role and evidence.

Analytics support (kentik_api.analytics)

V5 path: kentik_api/analytics/ with mapped_query.py, flatness.py, data_frame_cache.py, and a README. It shipped with the optional extra kentik-api[analytics], which installed pandas, PyYAML, and fastparquet.

What it provided:

  • Saved query definitions. SQLQueryDefinition and DataQueryDefinition hold a query and a column mapping, written in Python or in a YAML file, with {start} and {end} placeholders.
  • Results as pandas DataFrames. get_data(api, start=..., end=...) runs the query and returns a DataFrame. A top-X query returns one DataFrame for each bucket, and it can unpack the time series of each row.
  • A local cache. DFCache stores DataFrames as parquet files by time range, fetches only the missing time steps, and removes duplicate rows.
  • Flat-traffic detection. flatness_analysis uses DeviceCache to get interface speeds, converts traffic to percent of link use, and reports time windows where outbound traffic on a link stayed flat. On a perimeter link, flat traffic suggests a bandwidth limit in a peer network.

Who used it: data scientists and network engineers who analyze flow data in notebooks or scheduled jobs.

What users lose: there is no way to get flow or traffic data through the SDK, as DataFrames or in any other form. The two analytics examples cannot be ported.

Why V6 does not have it: the analytics package called POST /api/v5/query/sql and POST /api/v5/query/topXdata. The V6 schema publishes no query, SQL, or top-X service. journeys.get_nlq converts a plain-English question to a query object but does not run it.

What can be restored:

  • The pandas-only parts (DFCache, dedup_data_frame, the flatness statistics) do not call the API. They work on DataFrames from any source.
  • The query parts need a query endpoint. That needs either upstream schema work or a hand-written V5 query client outside the generator.
  • If the YAML mapping is ported, remove the @fixup: mapping type. It runs eval() on text from the YAML file, which allows code injection.

The rate limiting guide still quotes a separate Query API limit from the Kentik Knowledge Base.

Live check of the V5 API (2026-10-16)

scripts/v5/live_probe.py sent read-only calls to https://api.kentik.com with the project credentials. It prints status codes, response shapes, and quota headers only. The Admin APIs and Query API pages of the Kentik Knowledge Base mark V5 as deprecated, but list these endpoints.

V5 endpoint Result V6 equivalent

GET /customApplications 404 Yes: custom_application
GET /mykentik/tenants 404 Yes: mkp
GET /alerts-active/alarms, /alerts-active/alerts-history 200 Yes: alerting.alert_list. A live call with states=[ALERT_STATE_CLEAR] and a 30-day startedAt returned 138 cleared alerts
POST /alerts/manual-mitigate Not called (writes) Yes: alerting.mitigations_create

POST /query/url 200, a JSON string with a portal link None
POST /query/topXchart No response in 180 s, for SVG and PNG. A manual retest with the Knowledge Base example body also timed out, while topXdata answered the same body in 1.4 s None
POST /query/sql 403 Access Denied. The Knowledge Base says Kentik retired it on 2025-05-01 None
GET /batch/<guid>/status 404 Could not find this batch for an unknown ID, so the endpoint answers None
POST /batch/tags, /batch/customdimensions/<name>/populators Not called (writes) None. V6 device has bulk calls, but only for devices

Other findings:

  • V5 sends no X-RateLimit-* headers. V6 sends x-ratelimit-limit, x-ratelimit-remaining, and x-ratelimit-reset. So the SDK cannot report quota for a V5 call.
  • A query needs device_name even when all_selected is true. Without it, the API returns 400 The device_name is required.
  • V5 uses its own hosts: https://api.kentik.com/api/v5 (US) and https://api.kentik.eu/api/v5 (EU). V6 REST uses grpc.api.kentik.com.
  • A V6 alert_list call with states=[ALERT_STATE_ACTIVE] and a startedAt range returned 400 backend request error. Investigate before you document active-alert polling with a time filter.

Result: only the query (topXdata, url, and maybe topXchart) and batch endpoints have no V6 equivalent. Every other V5 endpoint has one, so the SDK maps those in the migration guide instead of adding them again.

Connection behavior

Behavior V5 V6 Status
Auth headers X-CH-Auth-Email, X-CH-Auth-API-Token Same headers, also on gRPC Kept
Retries 3 retries with backoff on 429, 502, 503, 504, for every method. Replaceable with retry_strategy= 2 retries of a failed connection only. No retry after a response Partial, by design: V6 never sends a write twice
Rate limits RateLimitExceededError, usually absorbed by the retries HTTPException with status_code == 429 and a rate_limit attribute. Quota recorded per endpoint Changed. More information, no automatic backoff
Timeouts Connect 10 s, read 60 s, REST only timeout, rest_timeout, grpc_deadline, and with_timeout() per call Kept and improved
Proxy proxy= argument or KTAPI_PROXY. SOCKS supported Standard proxy variables only. No SOCKS Partial
Host Any host through api_host= region="us" or "eu". A custom REST host only per call Partial
Logging Debug log of each request None Missing
User-Agent kentik_community_sdk_python/<version> Library default Missing
Unknown enum values Accepted (ADR 0003) Rejected. The call raises HTTPException(502) Changed. Reliability risk

Errors

V5 V6
KentikAPIError KentikError
AuthError (401 and 403) AuthenticationError (401). A 403 is an HTTPException
TimedOutError, UnavailabilityError, IntermittentError TransportError
BadRequestError, NotFoundError, RateLimitExceededError, ProtocolError HTTPException with status_code, and a generated class for each operation
DataFormatError, DeserializationError, IncompleteObjectError Pydantic validation, or HTTPException(502) for an unusable response

V6 has no "safe to retry" base class like IntermittentError. Callers check status_code instead.

Recommended follow-up

  1. Done: Kentik confirmed that the V5 query and batch endpoints still answer and that a V6 query service is planned. The live check above confirms it, except for query/sql (retired) and query/topXchart (no response). Feature 005 (specs/005-v5-query-batch/) covers the rest.
  2. Accept unknown enum values in response models, as V5 did, so that a new value from the API does not fail calls.
  3. Add a User-Agent header and debug logging to request_json() and call_grpc().
  4. Add a documented caller-side retry recipe for 429 to the rate limiting guide, using exc.rate_limit.
  5. Decide whether to add small helpers: credential profiles, DeviceCache (JSON, not pickle), a proxy= argument, and a custom host.
  6. Add create, update, and delete examples, and examples for the 7 services that have none.
