# V5 query and batch calls

`client.v5` calls the Kentik V5 endpoints that have no V6 equivalent: the
query API and the batch API. Every other V5 endpoint has a V6 replacement, so
the SDK does not add it again. [Migrating from 1.x](migrating-from-1x.md) maps
each 1.x call to its 2.x call.

`client.v5` is a bridge. Kentik marks the V5 API as deprecated and plans a V6
query service. Until that service ships, these calls are the only way to get
flow data through the SDK.

| Call | V5 endpoint | Returns |
| --- | --- | --- |
| `top_x_data(data=QueryRequest)` | `POST /query/topXdata` | `TopXDataResponse`: the rows of each bucket |
| `top_x_chart(data=ChartRequest)` | `POST /query/topXchart` | `ChartResponse`: a data URI. Not verified, see below |
| `query_url(data=QueryRequest)` | `POST /query/url` | `str`: a Data Explorer link |
| `batch_tags(data=BatchPart)` | `POST /batch/tags` | `BatchResponse`: the batch `guid` |
| `batch_populators(dimensionName=..., data=BatchPart)` | `POST /batch/customdimensions/{dimensionName}/populators` | `BatchResponse` |
| `batch_status(guid=...)` | `GET /batch/{guid}/status` | `BatchStatus` |

The SDK generates these calls from a hand-maintained description of the V5
endpoints, `schema/openapi/v5/v5/v5.swagger.json`. Each call raises the same
error types as every other 2.x call. The reference page is
[v5](../services/v5.md).

## Host and transport

The V5 API has its own host. The client picks it from its region:

| `region` | V5 base URL |
| --- | --- |
| `"us"` (default) | `https://api.kentik.com/api/v5` |
| `"eu"` | `https://api.kentik.eu/api/v5` |

For another host, pass `v5_base_url`. It must use `https`:

```python
client = KentikAPI(v5_base_url="https://kentik.example.net/api/v5")
```

The V5 endpoints exist only on REST. Every client has a REST connection to
the V5 host, so `client.v5` works on a client created with `protocol="grpc"`
too. `client.v5_api_config` is the configuration of these calls. Use it for a
per-call override:

```python
response = client.v5.top_x_data(
    data=request, api_config_override=client.v5_api_config.with_timeout(300)
)
```

## Query

```python
from kentik_api.client import KentikAPI
from kentik_api.gen.v5.models import Query, QueryItem, QueryRequest

client = KentikAPI()
query = Query(
    metric="bytes",
    dimension=["Proto"],
    device_name="router1,router2",
    lookback_seconds=3600,
    topx=8,
    depth=25,
    outsort="avg_bits_per_sec",
)
response = client.v5.top_x_data(
    data=QueryRequest(queries=[QueryItem(query=query, bucket="Left +Y Axis")])
)
for row in response.results[0].data:
    print(row["key"], row["avg_bits_per_sec"])
```

Things to know:

- The API needs `device_name`, even when `all_selected` is true. Without it,
  the call raises `HTTPException` with status 400 and the message
  `The device_name is required`.
- A result row is a `dict`, because its columns depend on the query.
- `Query` and `QueryItem` keep every field they get. Query JSON from 1.x, or
  from **Show API Call** in Data Explorer, works unchanged:
  `QueryItem.model_validate(copied_json)`.
- The models declare no enums. Pass `"bytes"`, not `MetricType.bytes`, and an
  unknown value from the API never fails a call.
- Kentik retired the V5 SQL endpoint on 2025-05-01. There is no SQL call.
- V5 sends no rate limit headers, so V5 calls report no quota. See "V5 calls
  report no quota" in the [rate limiting guide](rate_limiting.md).

## Chart (not verified)

`top_x_chart` returns the chart as a data URI. `decode_chart()` turns it into
bytes:

```python
from kentik_api.gen.v5.models import ChartRequest
from kentik_api.v5_tools import decode_chart

chart = client.v5.top_x_chart(
    data=ChartRequest(queries=[item], imageType="png"),
    api_config_override=client.v5_api_config.with_timeout(180),
)
image = decode_chart(chart)
open("chart.png", "wb").write(image.data)
```

In a live check on 2026-10-16, this endpoint gave no response within 180
seconds, for SVG and PNG, while `top_x_data` answered the same query in about
1.4 seconds. The call raises `TransportError` when it gets no response. Until
Kentik confirms the endpoint, use `query_url` for a chart in the portal, or
draw the rows of `top_x_data` yourself.

A chart call that gets no answer can still hold one of the Query API's four
concurrent slots on the server after the SDK gives up. In the live check, the
next queries then timed out for several minutes. Do not call `top_x_chart` in
a loop, and do not call it right before other queries.

### Test the chart call by hand

These steps call the endpoint directly, without the SDK, so the result shows
the endpoint's own behavior.

1. Get a known-good request body. In the portal, open **Data Explorer**, build
   a query on a device that has traffic, and click **Apply Changes**. Open the
   chart's options menu, select **Show API Call**, choose **Chart**, then click
   **JSON** and **Copy**. Save the JSON as `chart-query.json`. Set
   `"imageType": "png"`, and make sure that `device_name` is set.
2. Load your credentials into your own terminal session. Do not do this in
   code that other processes share:

   ```sh
   set -a; source .env; set +a
   ```

3. Call the endpoint with a 10-minute limit:

   ```sh
   curl -sS -m 600 -o chart.json -w '%{http_code} %{time_total}s\n' \
     -X POST -H "X-CH-Auth-Email: $KENTIK_EMAIL" \
     -H "X-CH-Auth-API-Token: $KENTIK_API_TOKEN" \
     -H 'Content-Type: application/json' -d @chart-query.json \
     https://api.kentik.com/api/v5/query/topXchart
   ```

   For an EU account, use `api.kentik.eu`.
4. If the status is `200`, decode the image and open `chart.png`:

   ```sh
   uv run python -c "import json,base64; u=json.load(open('chart.json'))['dataUri']; open('chart.png','wb').write(base64.b64decode(u.split(',',1)[1]))"
   ```

5. To compare, send the same body without `imageType` to `/query/topXdata`.
   It answers in a few seconds when the query is valid.
6. Report the result to Kentik support: the status code, the time, the
   `errorxid` if one comes back, and the request body. Never send the
   credentials. curl exit code 28 means that the endpoint did not answer in
   the time limit.

When a live call returns a chart, update this section and the
`top_x_chart` test in `tests/e2e/test_v5_query_e2e.py`, which expects a
timeout until then.

## Batch

A batch creates, updates, or deletes many flow tags, or the populators of one
custom dimension, in a few calls. The helpers in `kentik_api.v5_tools` follow
the API's rules: each part is at most 4 MB, only the last part is marked
complete, and every part after the first carries the batch `guid`.

```python
from kentik_api.gen.v5.models import BatchCriterion, BatchDelete, BatchUpsert
from kentik_api.v5_tools import send_batch, split_batch, wait_for_batch

upserts = [
    BatchUpsert(value="web", criteria=[BatchCriterion(addr=["192.0.2.10/32"])]),
]
parts = split_batch(upserts, [BatchDelete(value="old_tag")], replace_all=False)
guid = send_batch(client.v5.batch_tags, parts)
status = wait_for_batch(client, guid, timeout=600, interval=5)
print(status.upserts.applied, status.deletes.applied)
```

For populators, bind the dimension name:

```python
from functools import partial

guid = send_batch(
    partial(client.v5.batch_populators, dimensionName="c_my_dimension"), parts
)
```

- `replace_all=True` deletes every tag or populator that the batch does not
  upsert. Use it only when the batch holds the full set.
- The SDK never resends a part. If a part fails, `send_batch` raises
  `BatchSendError` with the `guid` and the number of parts sent.
- `wait_for_batch` raises `BatchWaitTimeout` with the last status when the
  time limit expires. The last status is `None` if no status arrived.

`timeout` and `interval` must be finite and positive. Other values raise
`ValueError` before any status request or sleep. One deadline covers
requests, result handling, and sleeps. Each request keeps tighter client
limits and shares the existing V5 connection. No poll starts at or after
expiry, and a status received that late does not return success.

A request timeout observed at or after the deadline becomes
`BatchWaitTimeout`, with the original `TransportError` as its cause.
The HTTPX timeout remains in that cause chain. This policy uses observation
time, even if the underlying limit expired earlier. Timeouts observed
before the deadline and all non-timeout errors propagate unchanged.
Failed status requests are not retried by the helper.

The SDK classifies fully buffered responses before checking their deadline.
HTTP and JSON errors from those responses retain their normal types,
including when the response arrives late. An unfinished response stream
can time out before the SDK receives and decodes its complete body.

The deadline is cooperative. Blocking operations can finish after expiry.
The SDK rejects late completion but does not force cancellation at an
exact wall-clock instant.

## Analytics with pandas

The 1.x `kentik_api.analytics` package is back, behind an extra:

```sh
pip install "kentik-api[analytics]"
```

It installs pandas, pyarrow, and PyYAML. Without the extra,
`import kentik_api.analytics` raises `ImportError` that names it, and the rest
of the SDK still works.

| 1.x | 2.x | Change |
| --- | --- | --- |
| `DataQueryDefinition.from_file`, `from_dict`, `get_data(api, ...)` | Same names. `get_data(client, ...)` calls `client.v5.top_x_data` | A definition file is read with `yaml.safe_load` |
| `SQLQueryDefinition` | Raises `ValueError` | Kentik retired the SQL endpoint |
| `"type": "@fixup: <lambda>"` | Raises `ValueError` | It ran Python code from the definition. Change the DataFrame in your own code after `get_data()` |
| `DFCache` | `DFCache` | `fetch` with `step` skips steps that a cached file already holds. File names use `_` in place of `:`, so the cache works on Windows. It still reads 1.x file names |
| `flatness_analysis` | `flatness_analysis` | Same inputs and output |
| `kentik_api.utils.DeviceCache` | `kentik_api.devices.DeviceLookup` | In the base install. `save()` and `load()` use JSON, not pickle |

A cache file is Parquet and a lookup file is JSON, so reading either cannot
run code. [`examples/v5/analytics_topx.py`](../../../examples/v5/analytics_topx.py)
is the 1.x flat-traffic example, ported.

`DFCache.fetch_latest()` fetches from the newest cached time to the current
UTC minute. If the cache is empty, it fetches the last 23 hours and
59 minutes. If the newest time equals or exceeds the current minute, it
returns `None` without querying or changing files. Use `cache.get()` to
read earlier data. A later refresh fetches only the new interval.
Explicit invalid ranges in `fetch()` and `get()` still raise `ValueError`.

## When the V6 query service ships

When Kentik publishes the V6 query service, the next schema update adds it to
the SDK under its own name. `client.v5` stays, and its calls keep working
until Kentik retires the V5 endpoints. This guide will then name the V6
replacement of each call.
